## Context

- `EntryStatus::Waiting(String)` and `Unavailable(String)` hold free text ("listed", "downloading 40%", "needs yt-dlp", "no clip", "clip failed"), set in several places in the dig code.
- `row_look` draws that text, dimmed, where the duration goes.
- The playlist row already has a right-click menu (`Popup::context_menu`): Send to crate, Render show, and the dig items Keep, Pass and Open for-sale page. Control-click works on macOS.
- There's no hover tooltip on rows.

## Goals / Non-Goals

**Goals:**
- A status you can read at a glance, and more room for names.
- Everything about an entry visible without playing it.
- Common per-entry actions without keyboard shortcuts.

**Non-Goals:**
- Columns (`playlist-columns`).
- Editing entry metadata.
- Batch Keep or Pass from the menu (verdicts stay per entry, as dig-verdicts specifies).

## Decisions

**1. Status kinds.**
```
Waiting(WaitKind):  Listed | Queued | Downloading(u8 %) | NeedsYtDlp | Other(String)
Unavailable(UnavailableKind): NoClip | ClipFailed | Other(String)
```
- There is no "preparing" kind: a downloaded preview is already playable while it is prepared.
- `note()` stays: it renders the kind back to the same wording, now used by the tooltip and by tests.
- Each kind's `Display` wording converts back with `From<&str>` ("listed", "downloading N%", "needs yt-dlp", "no clip", "clip failed"); anything else becomes `Other`, shown with a generic icon. Saved crates keep storing the wording, so old and new crate files are the same format.
- The UI code sets kinds directly. The `dig` crate keeps reporting its reasons as text ("no clip", "not found", "clip failed"), and they are converted where they enter the UI.

Alternative: keep strings and pick icons by matching the text. Rejected, because it is brittle and the text would drift from the icons.

**2. Icons are skin sprites.**
- They are one row high (`pl_row_h`) and generated by `skin-gen`, in the playlist's text colour so they dim the same way.
- `Downloading` is drawn as a 3-pixel-high bar filling the duration slot's width in proportion to its percentage. It's the only one that animates, and it repaints only when the percentage changes (low idle cost).

**3. The tooltip uses egui `on_hover_ui`.**
- It shows after egui's default delay and is built lazily, only for the hovered row.
- It shows the untruncated name, and origin fields that are empty are left out.
- The for-sale age reads "fetched 3 h ago".
- Nothing in it is clickable. Links live in the context menu, because a tooltip disappears when the pointer moves.

**4. Which entries the menu acts on.**
- Clicked entry inside the selection: Remove and Send to crate act on the whole selection.
- Clicked entry outside the selection: the selection first moves to the clicked entry (as in Finder and file lists).
- Keep, Pass, Open, Copy, Play and Render always act on the clicked entry only.

**5. Discogs links.**
- "Open release on Discogs" opens `https://www.discogs.com/release/<id>`, or `/master/<id>` for a master-only origin.
- "Copy Discogs link" puts the same address on the clipboard.
- Both are hidden for entries without an origin.

## Risks / Trade-offs

- [Icons are less explicit than words] → the tooltip always gives the reason, and the shortcuts help gets a small legend.
- [Old saved crates with unusual strings] → `Other(String)` keeps them, with a generic icon.
- [The spec text overlaps dig-titles' "Playlist display" block] → this change's MODIFIED block is written on top of dig-titles' version. Archive dig-titles first.
