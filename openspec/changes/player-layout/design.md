## Context

`App::window_size` stacks main, then waveform, then EQ, then playlist, at the skin's main width (275 × scale). The playlist is drawn from fixed-width sprites (`pl_top`, `pl_bottom`, `pl_left`, `pl_right`, 275 wide) and resizes only vertically, in row steps (`pl_resize`, `settings.playlist_rows`). Keys go through `transport_key`, then `window_key`, and ↑ and ↓ are hard-wired to volume. egui text fields already block the shortcuts (`egui_wants_keyboard_input`). The skin is generated by `skin-gen`, and a test checks that it matches.

## Goals / Non-Goals

**Goals:**
- A wide, tall playlist next to a player that keeps its classic size.
- A keyboard-first list without losing ↑ and ↓ for volume.
- One OS window, one wgpu surface (launch < 300 ms unchanged).

**Non-Goals:**
- Separate or undockable windows (option A in the exploration).
- Columns and sorting (`playlist-columns`).
- Type-to-filter.

## Decisions

**1. Two columns in one viewport.**
```
┌── left: fixed (main_size.0) ──┬── playlist: playlist_width ──┐
│ MAIN                          │ PL top bar (tiled to width)  │
│ WAVEFORM (if shown)           │ rows …                       │
│ EQ (if shown)                 │                              │
│ (empty space, painted bg)     │ PL bottom bar           [⤡]  │
└───────────────────────────────┴──────────────────────────────┘
```
- width = main width + (playlist shown ? `playlist_width` : 0);
- height = max(left column height, playlist height);
- the playlist height is also clamped to at least the left column height.

Any leftover space under the left column is filled with the skin's panel background. Rejected alternative: a second viewport (as the spectrogram uses). It means a second surface, window snapping, and Wayland's inability to place windows; the user chose side by side.

**2. Stretchable playlist chrome.**
`skin-gen` splits the playlist's top and bottom bars into a left cap, a tileable middle and a right cap, which is how Winamp 2 did it. The row area simply widens. The minimum width is `pl_width` (275). Horizontal resize is in whole points (free), vertical in whole rows. Drags accumulate as today (`pl_resize_acc`).

**3. Focus is a small enum on `App`: `Focus::Player | Focus::Playlist`.**
- A primary click anywhere in a section sets it; `Tab` toggles.
- Fullscreen ignores focus: ↑ and ↓ there stay volume.
- Title bars get a dimmed sprite variant, drawn when their side isn't focused. Main and EQ light together, because the player side is one focus zone.
- Hover never moves focus, and the mouse wheel scrolls whatever is under the pointer.

**4. Cursor versus selection.**
The playlist gets `cursor: Option<EntryId>`, which is not saved.
- Plain ↑ and ↓ move the cursor and make the selection just the cursor, as file lists do.
- Shift extends the selection from the anchor.
- Enter plays the cursor entry, falling back to the first selected entry, which keeps today's Enter.
- A mouse click moves the cursor to the clicked row.
- An entry removed or replaced by dig expansion moves the cursor to the entry now at the same index.

The cursor is an `EntryId`, not an index, so progressive dig filling doesn't make it jump.

**5. Following the playing entry.**
- On a track change, if the previous current entry was inside the visible rows, scroll the minimum amount to show the new one.
- `P` always scrolls to the playing entry and moves the cursor there, switching the shown crate to the playing crate if they differ.

**6. Removing balance.**
- `Settings.balance` is removed. serde ignores the unknown key in old files.
- At startup the engine is never given a balance, so it stays at its default of 0.
- `Action::Balance`, the balance sprites and the layout entries go.
- The waveform button takes the balance track's rectangle. It is a two-state skin button (`wave_btn`, `wave_btn_on`), and a click toggles `show_waveform` exactly like `W`.

## Risks / Trade-offs

- [Clash with beatmatch-automix, which also rewrites the "Transport and sliders" and "Keyboard shortcuts" requirements and the main window's button row] → whichever change is archived second rebases its MODIFIED blocks onto the other's. The skin work should be done together to avoid regenerating twice. Note that beatmatch-automix's current "Keyboard shortcuts" text predates the dig keys (Y, N, I, Cmd+V) and must regain them.
- [A very wide playlist on a small screen] → clamp the width so the window fits the current monitor when the size is restored.
- [The window gets taller than the left column when the playlist is tall] → intended; the left column's empty space is painted.
- [Users who relied on ↑ and ↓ as volume while working in the list] → the player is focused at launch, and one click on the player restores it.

## Migration Plan

Old settings files load unchanged: the unknown `balance` is ignored, and `playlist_width` defaults to 275. Rollback means reverting; old builds reading new settings see `playlist_width` as unknown and ignore it.
